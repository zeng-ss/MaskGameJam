## 第六轮：修 Generate Code 的 CS1615 / CS0306

新配置重新生成后报 474 个错，去重后只有两类实质问题，根因是 **xLua 2.1.15（2020 年）的生成器不认识 Unity 6 的新 API**：

2. **CS0306（126 个）**：Unity 6 新增了 `Span<Vector3>` 等参数的重载，`Span<T>` 是 ref struct


1. `ExampleConfig.cs` 新增 `private static readonly HashSet<string> EditorOnlyMembers`，

3. `List<List<string>>` 里只保留属性/无参方法条目（`Material.parent` / `isVariant`、两个 `OnRebuildRequested`），

## 【三轮】构建通过后运行时报错 + Lua 地址改为文件名

用户反馈：Addressables 构建**成功了**，但运行 Play 时抛
`Exception: Attempting to use an invalid operation handle`，
堆栈指向 `HotUpdateSystem+<LoadLuaScripts>d__20.MoveNext() (Assets/Scripts/AOT/HotUpdateSystem.cs:329)`。
另外提出需求：Addressables 的 Lua 分组地址能不能用**文件名**而不是路径。

### 问题 1：invalid operation handle 的根因
第 327 行原来是：
```csharp
AsyncOperationHandle luaHandle = Addressables.DownloadDependenciesAsync(luaGroupKey, true);
yield return luaHandle;
if (luaHandle.Status != AsyncOperationStatus.Succeeded)   // ← 抛异常
```
`DownloadDependenciesAsync(object key, bool autoReleaseHandle)` 的第二个参数是 **autoReleaseHandle**，
传 `true` 表示操作完成后**自动释放句柄**。编辑器 Play（Use Asset Database / 本地模式）下该操作会**同步完成**，
等于「刚拿到句柄就被释放」，所以紧接着访问 `.Status` 必抛
`AsyncOperationHandle.get_InternalOp()`（AsyncOperationHandle.cs:466）的异常。

**修复**：传 `false` → `yield return` → 用 `luaHandle.IsValid()` 兜底 → 用完手动 `Addressables.Release(luaHandle)`。
`IsValid()` 顺带覆盖了「label 在 catalog 里不存在 → 返回无效句柄」这种情况，给出可读的 warning。
（分组和 label 本身没问题，`Lua.asset` 里 4 个条目都带 `Lua` label。）

### 问题 2：地址改为纯文件名
原规则 `lua/ + 相对路径`（`lua/demo/greet.lua`）→ 新规则**纯文件名**（`greet.lua`）。

## UI 层迁移后运行时验证：修掉「缓存场景对象被销毁」与「退出时 LuaEnv 释放失败」

### 症状（第 2 次进 EndlessScene 的**第一帧**开始，共 2296 条）
```
LuaException: c# exception:Non-static method requires a target.
  at XLua.OverloadMethodWrap.Call (MethodWarpsCache.cs:242)
stack traceback:
	[C]: in method 'GetFinalMaxHealthValue'
	player_pro_panel:58
```
以及退出时 2 条 `InvalidOperationException: try to dispose a LuaEnv with C# callback!`。

> 排查提示：`Editor.log` 是**跨会话累积**的（22 MB / 14 万行），里面 39702 条 `error CS`
> 全是旧 asmdef 时代残留（报错路径里带 `Library/Bee/artifacts/*/XLua.ref.dll`）。
> 判断"当前会话报什么错"要先定位最后一次 `LUA: [lua] main.lua loaded` 的行号，只看它之后的日志。

### 根因 1：Lua 缓存的场景对象被销毁后仍是「非 nil 的 userdata」
时序证据：`StartScene → EndlessScene → StartScene → EndlessScene`，错误**恰好从第 2 次
EndlessScene 的第一帧**开始。链路：
1. `UIManager` 用 `UIPanelDict` 缓存面板，重开走 `panel.Show()`，**不会重跑 `Awake`**；
2. `PlayerProPanel.lua` 的 `self.playerStats` 是第 1 次 EndlessScene 里的玩家，切场景后已被销毁；
3. `XLuaManager.Update()` 每帧调 `_luaEnv.Tick()` → `ObjectPool.Check` →
   `ObjectValidCheck` 对**已销毁的 UnityEngine.Object** 返回 false → `Replace(index, null)`
   **把对象池槽位置空**；
4. 于是 Lua 侧 `stats ~= nil`（userdata 还在），但 C# 侧 `FastGetCSObj` 拿到的 target 是 null →
   `MethodBase.Invoke(null, args)` 对实例方法抛 `TargetException: Non-static method requires a target`。

🔴 **这是 xLua 的通用坑，不是本项目的特殊问题**：`obj ~= nil` 判断不出"Unity 对象已销毁"。
**凡跨帧缓存 C# 场景对象（玩家/敌人/子弹/面板外的物体），每帧用之前必须校验存活。**

### 解法
- `LuaBinding` 新增 **`public static bool IsAlive(UnityEngine.Object obj) => obj != null;`**
  （用 Unity 的 null 语义；传 nil 或槽位已置空的 userdata 都会安全地返回 false，
  因为 `ObjectCasters.genCaster` 的 `fixTypeGetter` 对非 userdata 返回 null、
  对 `SafeGetCSObj` 拿到 null 时也返回 null）
- `player_pro_panel.lua`：新增 `ensure_player_stats()`，`update` 里每帧校验
  → 死了就 `resolve_player_stats()` 重找；`onenable`/`show` 也各校验一次。
  `resolve_player_stats` 里**换玩家时重置** `isInitPlayerHealth` 和文本缓存哨兵值。

### 根因 2：退出时 `try to dispose a LuaEnv with C# callback!`
`LuaEnv.Dispose()` 在 `translator.AllDelegateBridgeReleased()` 为 false 时直接抛。
我们通过 `LuaTable.Get<Action>("update")` 等拿到的生命周期委托，以及面板上的
`AddListener(function() ... end)` 闭包，xLua 都算「C# callback」；只要 C# 侧还持有
`LuaTable` / 委托引用，`delegate_bridges` 里的 WeakReference 就还活着 → 拒绝释放。
（旧代码里这个异常还会让 `_luaEnv` 不被置空，于是 `OnApplicationQuit` + `OnDestroy`
各抛一次，正好 2 条。）

### 解法
- `LuaBinding` 新增静态 `s_activeBindings` 列表 + **`DisposeAll()`**：
  逐个 `Dispose()`（清 `_luaUpdate` 等委托、`Dispose` 掉 LuaTable）+ 清 `s_instanceMap`
- `XLuaManager.Dispose()`：**先 `LuaBinding.DisposeAll()` 再 `_luaEnv.Dispose()`**，
  并把 `Dispose()` 包进 try/catch —— 退出时场景里的 UnityEvent 闭包可能还没被 GC 回收，
  这时只记一条 warning，不再抛异常、不再刷堆栈
- `LuaBinding.CallLua` 加了三条可读 warning（目标为空 / 未绑定 Lua 实例 / Lua 里没这个方法），
  以前是静默返回 null，排查很痛苦

## 第 2 批运行时验证：空 Unity 对象字段导致「伤害丢失 / 死不了 / 倒计时不工作」

### 报错
```
LuaException: c# exception:The variable sphereCollider of EnemyController has not been assigned.
  at UnityEngine.Collider.set_enabled (System.Boolean value)
stack traceback:
	[C]: in metamethod '__newindex'
	enemy_controller:52: in local 'fn'      ← cs.sphereCollider.enabled = true
	behaviour:35
  at LuaBinding.OnEnable ()  →  LuaBehaviour.OnEnable ()
```
日志里**只有这一个**异常，在每个 Cow 敌人生成时各抛一次（共 30 次），其它没有任何 warning。

### 根因
Lua 里 `if cs.sphereCollider ~= nil` 判断不出「空的 Unity 对象字段」——
**xLua 把空 Unity 对象 push 成非 nil 的包装**，于是走 then 分支直接访问 `.enabled` 抛异常。

### 为什么表现成三个不相关的 bug
`sphereCollider` 的访问在 `enemy_controller:onenable` 的**前几行**，异常中断了后面的赋值：
- `self.dataValid` / `self.currentHealth` 没赋值 → 敌人打不死（`decrease_health` 里同一行也会抛，
  `self.isDead = true` 执行不到）
- `robot_controller:onenable` 里同样位置 → `self.hitBlood` 没赋值 →
  `EnemyBulletController.init(_, nil)` → 玩家挨枪不掉血 → 玩家死不了
- `EnemySpawner:start` 的后续步骤（打开倒计时面板）也可能被跳过 → 面板显示但没有倒计时

### 解法
1. C# 壳加安全方法（C# 里 `!= null` 用 Unity null 语义，才可靠）：
   - `EnemyController.SetBodyColliderEnabled(bool)`（sphereCollider 优先，没配则 capsuleCollider）
   - `RobotController.SetSphereColliderEnabled(bool)`
   - `WeaponController.SetHitColliderEnabled(bool)`
2. **全部 Unity 对象空判断统一换 `CS.LuaBinding.IsAlive(obj)`**，禁止 `~= nil`：
   `PoolMgr.GetObj` 返回值、`GetComponent` 结果、`SceneObjectManager` 返回、面板回调 panel、
   `getPanelByName` 结果、`startTarget/endTarget`、`targetModel`、`fireEffect`、
   缓存的 `characterController`、`cs.healthImage`、`cs:GetRain(i)`。
   涉及文件：enemy_controller / robot_controller / weapon_controller / parabolic_bullet /
   enemy_bullet_controller / mask_controller / mask_spawner / enemy_spawner /
   auto_generate_nav_path / model_rotate / key_binding_manager。
3. `EnemySpawner:start` 的 `preload_all_pools()` 包 `pcall`：某个敌人预制体缺组件时，
   只记一条 error，不再连带吞掉后面的倒计时面板。
4. `EnemySpawner:open_timer_panel` 加了诊断日志（打印 interval）与面板加载失败提示，方便下次定位。

### 教训（已写进 MEMORY.md）
> **Lua 里凡是对 Unity 对象做空判断，一律用 `CS.LuaBinding.IsAlive(obj)`，不要用 `~= nil`；
> 涉及 Unity 组件字段的，优先在 C# 壳里包成方法。**
> 这与第 1 批的「僵尸 userdata」是同一规律的两个面向：
> 已销毁对象是「非 nil 但调方法抛 Non-static method requires a target」，
> 空字段是「非 nil 但访问属性抛 The variable xxx has not been assigned」。

## 第 2 批验证第二轮：跨语言调用全部失效（behaviour.new 只暴露了生命周期）

### 报错（sphereCollider 那条已消失 ✅，说明上一轮修对了）
```
[enemy_spawner] 打开倒计时面板，interval=5.0          ← start 跑完了 ✅
[LuaBinding] CallLua 调用失败：TimerPanel 的 Lua 模块里没有方法 start_countdown()
[LuaBinding] CallLua 调用失败：ParabolicBullet 的 Lua 模块里没有方法 init_bullet()
[LuaBinding] CallLua 调用失败：EnemyBulletController 的 Lua 模块里没有方法 init()

LuaException: c# exception:Value cannot be null. Parameter name: key
  at System.Collections.Generic.Dictionary`2.ContainsKey (TKey key)
  at PoolMgr.PushObj (System.String name, UnityEngine.GameObject obj) PoolMgr.cs:128
	[C]: in method 'PushObj'
	enemy_bullet_controller:25: in local 'fn'          ← PoolMgr.Instance:PushObj(self.bulletType, ...)
```

### 根因
`behaviour.new()` 只返回一张**生命周期 handlers 表**（awake/start/update/…），
模块里的普通方法（`start_countdown` / `init_bullet` / `init` / `set_wave_text` / `show_tip`…）
**根本没有被暴露**，所以 `CallLua` 取不到、Lua 侧拿到的实例表上也没有。
`init` 调不到 → `self.bulletType` 永远是 nil → 子弹 5 秒后 `PushObj(nil, obj)` 抛
`Value cannot be null. Parameter name: key`（这就是日志里刷屏的那条）。

### 解法
`behaviour.new()` 改为**返回实例表 `o` 本身**（关键：不能再另建一张转发用的表，
否则 C# 侧和 Lua 侧拿到的 self 不是同一个，`self.xxx = ...` 会写到不同的表上，状态分裂）：
1. 生命周期：`o[name] = function() local fn = cls[name]; if fn then fn(o) end end`（绑死 self，C# 按 Action 取）
2. 普通方法：`o[k] = cls[k]`（`pairs` 原样复制，**不绑 self**）
   —— 用 rawset 复制而不依赖 `__index`，就不用赌 `xlua_pgettable` 是否触发元表

`LuaBinding` 配套改动：
- 新增 `BuildCallArgs(self, args)`，把**实例表作为 self 插到实参最前面**
- `CallLua` / `InvokeLua` 都走它，于是 Lua 侧 `inst:foo(x)` 与 C# 侧 `CallLua(comp,"foo",x)`
  的 self 完全一致（都是那张 `o` 表）
- `GetLuaFunction` 只在实例**已绑定**时才写缓存：否则实例未就绪时缓存了 null，
  之后实例就绪也永远取不到（这是个潜伏 bug，已一并修掉）

## 第 3 批迁移：XQL 层 10 个 + GameLanuch → Lua（2026-10-11，最后一批）

### 范围与边界
迁：`Bullet`、`PlayerModle`、`PlayerModelAnimEventReceiver`、`TopDownCameraFollow`、
`PlayerStats`、`PlayerController`、`MaskSystemManager`、`PatternSelectUIManager`、
`MaskSelectUIManager`、`GameLanuch`（在 `HotUpdate/` 根目录，不在 XQL，注意别放错）。

**保留 C#**：`MaskFaction` / `BuffType` 枚举、`BuffData` / `PatternData` / `MaskData`。
理由：它们是 **Inspector 序列化数据**，被 `List<T>` 挂在 `MaskSystemManager` 组件上，
搬进 Lua 会把配置丢掉（或必须手工重抄，易错）。

### 关键手法
1. **扁平下标接口**：`MaskSystemManager` 壳暴露
   `GetMaskDataCount/GetMaskDataFaction(i)/GetMaskBaseBuffValue(i,j)`、
   `GetPatternDataCount/GetPatternName(i)/GetPatternBuffType(i,j)`、`GetRandomBuffType(i)` 等，
   Lua 侧完全不碰 `List<MaskData>` / `List<PatternData>` / `List<BuffData>`。
2. **跨语言传下标而不是对象**：`unlock_pattern_selection()` 返回 3 个花纹下标，
   `PatternSelectUIManager` 按下标反查文本、选择时回传下标。
3. **单例基类冲突**：`MaskSystemManager` 原继承 `UnitySingleTonMono<T>` →
   改 `LuaBehaviour` 后在壳里自实现 `Instance` + `DontDestroyOnLoad`（与 KeyBindingManager 同款）。
4. **单一真相源放在 C# 属性**：`IsMaskSelected` 留在壳上，Lua 与 C# 都读写它。
5. **`UnityAction<float>` 由壳创建**：`TopDownCameraFollow.BindSliderValueChanged(Slider)` /
   `UnbindSliderValueChanged(Slider)`，Lua 只传 Slider，避免依赖 `UnityAction<float>` 的 Lua 委托注册。
6. **`OnDrawGizmosSelected` 留在壳**（Lua 画不了编辑器辅助图形）。
7. **Lua 之间不用 C# 委托**：`PlayerModle` 的 `footStepAction`/`rootMotionAction`（`Action` 类型）
   改为 Lua function 字段 + `set_foot_step_handler/set_root_motion_handler`。
