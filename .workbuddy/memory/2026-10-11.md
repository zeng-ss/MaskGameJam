## 第六轮：修 Generate Code 的 CS1615 / CS0306

新配置重新生成后报 474 个错，去重后只有两类实质问题，根因是 **xLua 2.1.15（2020 年）的生成器不认识 Unity 6 的新 API**：

2. **CS0306（126 个）**：Unity 6 新增了 `Span<Vector3>` 等参数的重载，`Span<T>` 是 ref struct


1. `ExampleConfig.cs` 新增 `private static readonly HashSet<string> EditorOnlyMembers`，

3. `List<List<string>>` 里只保留属性/无参方法条目（`Material.parent` / `isVariant`、两个 `OnRebuildRequested`），

## 【三轮】构建通过后运行时报错 + Lua 地址改为文件名

用户反馈：Addressables 构建**成功了**，但运行 Play 时抛
`Exception: Attempting to use an invalid operation handle`，
堆栈指向 `HotUpdateSystem+<LoadLuaScripts>d__20.MoveNext() (Assets/Scripts/AOT/HotUpdateSystem.cs:329)`。
另外提出需求：Addressables 的 Lua 分组地址能不能用**文件名**而不是路径。

### 问题 1：invalid operation handle 的根因
第 327 行原来是：
```csharp
AsyncOperationHandle luaHandle = Addressables.DownloadDependenciesAsync(luaGroupKey, true);
yield return luaHandle;
if (luaHandle.Status != AsyncOperationStatus.Succeeded)   // ← 抛异常
```
`DownloadDependenciesAsync(object key, bool autoReleaseHandle)` 的第二个参数是 **autoReleaseHandle**，
传 `true` 表示操作完成后**自动释放句柄**。编辑器 Play（Use Asset Database / 本地模式）下该操作会**同步完成**，
等于「刚拿到句柄就被释放」，所以紧接着访问 `.Status` 必抛
`AsyncOperationHandle.get_InternalOp()`（AsyncOperationHandle.cs:466）的异常。

**修复**：传 `false` → `yield return` → 用 `luaHandle.IsValid()` 兜底 → 用完手动 `Addressables.Release(luaHandle)`。
`IsValid()` 顺带覆盖了「label 在 catalog 里不存在 → 返回无效句柄」这种情况，给出可读的 warning。
（分组和 label 本身没问题，`Lua.asset` 里 4 个条目都带 `Lua` label。）

### 问题 2：地址改为纯文件名
原规则 `lua/ + 相对路径`（`lua/demo/greet.lua`）→ 新规则**纯文件名**（`greet.lua`）。
好处：Lua 里 `require 'greet'` 直接对应地址，符合「引用按名称查找」的学习诉求。

改动：
1. `Build.cs`：删 `LuaAddressPrefix`；地址改用 `Path.GetFileName(path)` 去掉 `.txt`；
   `ListLuaAddresses` 改用 `entry.labels.Contains(LuaLabel)` 过滤（地址已无统一前缀）。
2. `XLuaManager.cs`：删 `LuaAddressPrefix`；loader 取 `filepath` 最后一段拼 `.lua`
   （`require 'greet'` 和 `require 'demo.greet'` 都命中 `greet.lua`，兼容旧写法）。
3. Lua 脚本：`main.lua.txt` 的 `require 'demo.greet'` → `require 'greet'`；
   `ui/start_panel.lua.txt` 的 `require 'framework.behaviour'` → `require 'behaviour'`；注释同步更新。
4. `StartPanel.cs`：`DefaultLuaModule` 由 `"ui.start_panel"` 改为 `"start_panel"`；
   `LuaPanel.cs` / `LuaBehaviour.cs` 的 Tooltip 文案同步。
5. 直接改 `Assets/AddressableAssetsData/AssetGroups/Lua.asset` 里 4 个 `m_Address` 为新值，
   这样即使用户先不跑 `Build/PrepareLuaAssets` 也能对上（菜单是幂等的，跑一次结果相同）。

### 注意事项
- 改地址后必须**重新执行 `Build/PrepareLuaAssets` 并重新构建 Addressables**，否则 catalog 里还是旧地址。
- **纯文件名方案下，不同目录不能有同名 Lua 文件**，否则地址冲突。当前 4 个文件名互不相同，安全。
- `default(AsyncOperationHandle)` / `IsValid()`：Addressables 里判断句柄可用性用 `IsValid()`，不要直接摸 `.Status`。
